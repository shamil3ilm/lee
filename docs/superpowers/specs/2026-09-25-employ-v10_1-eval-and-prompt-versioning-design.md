## 1. Overview

Three related additions:

- **A. Per-discovery scoring rows** — track an ai_call_log per scored discovery, unlock the dismiss = implicit 👎 signal deferred in v10
- **B. Prompt versioning** — hash every prompt at emit time, persist in ai_call_logs, correlate ratings across prompt/model changes
- **C. Eval fixtures + `pnpm eval`** — golden inputs per AI task; snapshot outputs; regression runner + CI gate

Together these prove the loop from v10: signal check → generate → rate → detect regression.

## 2. Feature A — Per-discovery scoring rows

### Data model
Add to `discoveries` and `company_discoveries`:
```sql
alter table discoveries add column scored_by_call_id uuid references ai_call_logs(id) on delete set null;
alter table company_discoveries add column scored_by_call_id uuid references ai_call_logs(id) on delete set null;
```

### Behavior
- Discovery scoring in `lib/discovery/service.ts` — after `ai.scoreJob(...)` / `scoreCompany(...)`, capture the ai_call_log row id (returned from `logCall`), persist onto the discovery
- Dismiss action (`dismissDiscovery` / `dismissCompanyDiscovery` in `app/(authed)/discoveries/actions.ts`) — after status update, if the discovery has `scored_by_call_id`, POST implicit signal `action='dismissed'` on that call
- Save action already writes an activity; extend to also POST `action='used'` on the linked call

### Result
Users dismissing low-quality matches automatically feeds negative signal to the scoring prompt/model. Save = positive.

## 3. Feature B — Prompt versioning

### Data model
```sql
alter table ai_call_logs add column prompt_hash text;
alter table ai_call_logs add column prompt_version text;   -- semver-ish or git-sha-ish
```

### Behavior
- New helper `lib/ai/prompts/hash.ts`:
  ```typescript
  export function hashPrompt(prompt: string): string  // sha256, first 12 chars
  ```
- Every prompt builder in `lib/ai/prompts/*.ts` gains a `VERSION` const at file top (semver: `'1.0.0'`)
- Providers' `logCall` accepts + persists `promptHash` and `promptVersion` metadata
- All generator services pass `{promptVersion: PARSE_JOB_PROMPT_VERSION, promptHash: hashPrompt(prompt)}` to the AI call

### Analytics extension
Extend `aiUsageStats` to break down rating by (kind, promptVersion) — surface which prompt versions are performing better/worse. Add to the AI Usage card.

## 4. Feature C — Eval fixtures + regression runner

### Directory layout
```
tests/eval/
  fixtures/
    parse-job/          # 5 hand-crafted JD snippets
      01-stripe-be.json
      02-remote-only.json
      03-minimal-signal.json
      ...
    tailor-cv/          # 5 (master, application) pairs
    outreach/           # 10 (master, application, kind, tone) triples
    prep-pack/          # 5 (master, application, stage) triples
    debrief/            # 3 (stage, quickNotes) pairs
    interview-prep/     # 3 mixed
  snapshots/            # golden outputs, gitignored, refreshable via `pnpm eval --update`
  run.ts                # runner
```

### Runner: `pnpm eval`
- Reads all fixtures under `tests/eval/fixtures/`
- For each fixture: run through `FixtureAIProvider` (deterministic) AND optionally through the real provider (if `EVAL_LIVE=1` env set + API key present)
- Compare fixture output against snapshot on disk
- Modes:
  - default: fail on any diff, print unified diff
  - `--update`: overwrite snapshots with current output (use after intentional prompt changes)
  - `--live`: run against real provider (Groq default); records outputs but doesn't fail on diff (real provider is non-deterministic)
- Prints summary table: task, fixtures run, passed, failed, avg latency
- Exit non-zero on any fail

### CI integration
Add step to `.github/workflows/ci.yml`:
```yaml
- name: Eval
  run: pnpm eval
```
Runs deterministic (fixture provider) evals on every push. Live evals stay opt-in via env.

### Snapshot ergonomics
- Snapshot file = `tests/eval/snapshots/{task}/{fixture-name}.json` (structured, easy to diff)
- Include a header comment: `// generated by pnpm eval --update on {date} with model={model}` for traceability
- Snapshots ARE checked into git (small, human-readable), unlike test outputs

### First-run setup
Running `pnpm eval` on a fresh checkout without snapshots → prints "no snapshots yet, run `pnpm eval --update` to create them" and exits 0. After update, all subsequent runs are regression checks.
